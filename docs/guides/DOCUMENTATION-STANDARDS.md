# استاندارد مستندسازی

**وضعیت:** Active  
**مرجع سیاست:** [ADR-000](../architecture/decisions/ADR-000-DOCUMENTATION-STRATEGY.md)

## زبان و نام‌گذاری

- متن توضیحی فارسی؛ نام فنی مانند `ICommandHandler`، `ActivitySource` و `HybridCache` انگلیسی.
- مسیرها، نام کلاس، Method و Namespace ترجمه نمی‌شوند.
- فایل‌های Markdown با نام انگلیسی و `KEBAB-CASE.md` نوشته می‌شوند.
- در مثال کد از نام‌گذاری و قراردادهای معمول زبان برنامه‌نویسی استفاده می‌شود.

## قالب Concept

1. مسئله و هدف
2. تعریف مفاهیم
3. وضعیت پیاده‌سازی فعلی و مسیر سورس
4. گزینه‌های قابل بررسی با Trade-off
5. سناریوهای استفاده و مثال
6. خطرها و محدودیت‌ها
7. پرسش‌های باز
8. معیار پذیرش و تست

## قالب ADR

- عنوان، شماره، تاریخ و وضعیت
- Context و مسئله
- گزینه‌های بررسی‌شده
- تصمیم تأییدشده
- دلایل و پیامدها
- تست‌ها، راه مهاجرت و شرایط بازبینی

## مستند راستی‌آزمایی

در ادعاهای مربوط به اجرا، شواهد لازم ثبت شود: نام Repository، Branch/Commit، دستور تست، نتیجه و محدودیت. **موفقیت تست حدس زده نمی‌شود.**

## نگهداری

- یک تصمیم Canonical داشته باشیم؛ محتوای متناقض را در چند فایل کپی نکنیم.
- تغییر یک تصمیم Accepted با ADR جدید یا Superseding انجام شود.
- تغییر رفتار کد باید مستندات مرتبط را در همان PR بررسی کند.
- هیچ Secret، Credential، Token یا اطلاعات شخصی در docs ثبت نشود.
